# ADR 0002: HITL 다중 상담원 처리를 Claim 선착순 모델로 처리

## Status
Accepted

## Context
여러 Tenant 팀원이 동시에 어드민 UI를 보고 있을 때 같은 HITL 세션에 응답하려 하면 충돌이 발생할 수 있다. 대안:
- **A) Claim 선착순**: 먼저 수락한 상담원이 세션을 소유. 나머지는 읽기 전용.
- **B) 자유 응답**: 충돌 제어 없이 누구든 전송 가능.
- **C) 초기 버전에서 무시**: 단일 상담원을 가정하고 나중에 추가.

## Decision
Claim 선착순 모델(A)을 초기 버전부터 구현한다. `EscalationClaim` 모델로 클레이머를 기록하고, DB 레벨의 unique constraint나 select_for_update로 동시 클레임을 방지한다.

## Consequences
- **장점**: 충돌로 인한 중복 메시지 발송 없음. 책임 소재 명확.
- **단점**: 초기 구현 복잡도 증가. 클레이머가 응답 없이 자리를 비울 경우 timeout/reassign 로직이 필요할 수 있음(현재는 스코프 외).
- **트레이드오프**: C(간단하게 시작) 대비 초기 비용이 있지만, 나중에 C→A 마이그레이션은 데이터 모델 변경을 수반하므로 처음부터 A가 더 합리적이라 판단.
