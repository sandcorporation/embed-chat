## What to build

어드민 인증의 핵심 deep module. Operator·TenantAgent의 로그인 세션을 Session Family 단위로 발급·회전·폐기하는 stateful Refresh Token 서비스와 그 영속 모델을 만든다. 이 슬라이스는 UI가 없고 실DB 단위테스트로 검증된다 — 이후 모든 슬라이스의 토대.

서비스 인터페이스(개념):
- `issue_session(subject) -> raw_refresh`: 새 Family 시작(최초 로그인). `family_expires_at = now + 14d`.
- `rotate(raw_refresh) -> raw_refresh`: 회전. 같은 family·`family_expires_at` 상속. 재사용/만료/폐기/미존재 시 명확한 예외.
- `revoke_family(family_id)` / `revoke_all(subject)`: 폐기.

`RefreshToken` 모델: nullable FK `operator`/`tenant_agent`(정확히 하나만 set — CHECK 제약), `family_id`(UUID, indexed), `token_hash`(원문 미저장·unique·indexed), `family_expires_at`, `used`(bool), `revoked`(bool), `created_at`.

회전 규칙(프로토타입 의사코드 — 결정 인코딩):
```
rotate(raw):
  row = lookup_by_hash(raw)               # 미존재 → reject
  if row.revoked: reject
  if row.used: revoke_family(row.family_id); reject   # 재사용=도난, family 일괄 폐기
  if now > row.family_expires_at: reject  # 절대 14일 캡(슬라이딩 없음)
  row.used = True; save
  return issue(family_id=row.family_id, family_expires_at=row.family_expires_at)
```

## Acceptance criteria

- [ ] `RefreshToken` 모델 + 마이그레이션: FK 2개(정확히 하나만 set 제약), `family_id`, `token_hash`(원문 비저장), `family_expires_at`, `used`, `revoked`
- [ ] `issue_session`이 새 Family와 14일 `family_expires_at`로 raw refresh를 발급
- [ ] `rotate`가 정상 토큰을 회전(같은 family, 상속된 `family_expires_at`, 옛 토큰 `used` 처리)
- [ ] 이미 `used`된 토큰으로 `rotate` 시 거부 + **해당 family 전체 폐기**(재사용 감지)
- [ ] `family_expires_at` 경과 시 회전 거부(절대 캡, 회전이 캡을 연장하지 않음)
- [ ] `revoke_family`/`revoke_all`이 대상만 폐기(다른 family 불간섭)
- [ ] 토큰 원문은 DB에 저장되지 않음(해시만)
- [ ] 실DB·실crypto 단위테스트: 회전·재사용감지·절대캡·다중기기 독립성·revoke_all
