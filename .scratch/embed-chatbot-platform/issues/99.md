# 99 — TenantAgent access/refresh end-to-end

Status: ready-for-agent

## Parent

[PRD-admin-access-refresh-auth.md](../PRD-admin-access-refresh-auth.md) · [ADR-0013](../../../docs/adr/0013-admin-access-refresh-token-auth.md)

## What to build

TenantAgent 로그인을 access/refresh 스킴으로 전환하는 end-to-end 수직 슬라이스. 98에서 구축한 프론트 `authFetch` 래퍼를 재사용한다.

백엔드: `POST /api/tenant/agents/auth/login`이 access(30분) + refresh 쿠키 반환. `POST /api/tenant/agents/auth/refresh`가 쿠키 refresh를 회전(새 access + 새 쿠키), 쿠키없음/만료/폐기/재사용 시 401. agent 쿠키는 operator와 별개 이름·경로.

프론트: TenantLogin/TenantDashboard가 sessionStorage access + `authFetch`(투명 refresh·부팅 silent refresh)를 사용. 구 agent 단일토큰 localStorage 경로 제거.

## Acceptance criteria

- [ ] TenantAgent 로그인이 access(body, 30분) + refresh(Set-Cookie, operator와 별개 이름·경로한정) 반환
- [ ] `/api/tenant/agents/auth/refresh`가 쿠키 refresh로 새 access + 회전 쿠키 반환
- [ ] 쿠키 없음/만료/폐기/재사용 refresh → 401
- [ ] TenantLogin/TenantDashboard가 sessionStorage access + authFetch 사용
- [ ] 앱 부팅 시 silent refresh로 agent access 복구
- [ ] 다중기기: 두 기기에서 각각 로그인 시 독립 Family(한쪽 폐기가 다른쪽 불간섭) — 엔드포인트 레벨 검증
- [ ] 구 agent 단일토큰 localStorage 경로 제거
- [ ] 백엔드 엔드포인트 테스트(실DB) + 프론트 vitest
