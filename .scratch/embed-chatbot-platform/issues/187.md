## What to build

slug 식별자가 완성형 한글을 받도록 백엔드를 end-to-end로 확장한다 — 등록부터 조회까지.

- `slug.py`: 정규식을 `[가-힣A-Za-z0-9](-?[가-힣A-Za-z0-9])*`로(선행/후행/연속 하이픈 금지 유지).
  `normalize_slug(raw)` = NFC + 앞뒤 trim(대소문자 보존), `slug_key(s)` = casefold 비교키.
  `is_valid_slug`는 normalize 기준 형식·길이(≤63)·예약어(slug_key 비교).
- `update_slug` API: 입력 normalize → 검증 → 중복검사 `slug__iexact` → 원형(NFC) 저장.
- `resolve_slug`(models): 입력 normalize 후 `slug__iexact`로 활성 Tenant 조회.

## Acceptance criteria

- [ ] 한글(`우리가게`)·영한혼합(`서울cafe`)·대문자(`MyStore`) slug 등록 가능
- [ ] 자모(`ㄱㄴ`)·한자(`商店`)·이모지·특수문자(`가@게`)·연속/선행/후행 하이픈 거부
- [ ] NFD(자모분리) 입력이 NFC로 저장된다
- [ ] `MyStore` 등록 후 `mystore`로 `resolve_slug` 조회 성공(대소문자 무시)
- [ ] `Store` 존재 시 `store` 중복 등록 400(대소문자 무시 유일성)
- [ ] 예약어 대문자 우회(`Admin`·`API`) 거부
- [ ] 기존 ASCII slug 등록·조회 유지(하위호환)
