# Provider 설정 + 키암호화 + ProviderResolver (LLM 라우팅)

## Parent

PRD: `.scratch/embed-chatbot-platform/PRD-per-tenant-providers.md` (ADR-0012)

## What to build

per-Tenant **LLM Provider**를 도입해 Tenant가 자기 키로 챗·추출 비용을 부담하게 한다. 이 슬라이스가 멀티 provider의 tracer다.

- **Provider 설정**: LLM Provider `{type: openai|anthropic|custom, base_url, api_key, chat_model, extraction_model}`. `TenantConfig.model_id` → `chat_model`로 흡수(migration).
- **키 암호화 deep module**: Fernet류 대칭 암호화(플랫폼 시크릿). 저장 시 암호화, API write-only, 조회 시 마스킹.
- **ProviderResolver deep module**: provider 설정 → LLM 클라이언트. openai/custom → OpenAI-호환, anthropic → Anthropic 네이티브. LLM 경계(챗·추출·메모리)가 전역 settings 대신 리졸버를 통해 per-Tenant 클라이언트를 얻는다.
- **dev 기본**: env 기반 폴백을 dev는 Custom 타입 로컬 fake-llm으로, prod는 비움(미설정 시 LLM 호출 불가).

## Acceptance criteria

- [ ] LLM Provider 설정(type·base_url·키·모델)을 어드민에서 저장·교체할 수 있다
- [ ] API 키가 암호화 저장되고 응답에 마스킹되어 평문 노출이 없다
- [ ] ProviderResolver가 openai/custom→OpenAI-호환, anthropic→Anthropic 클라이언트로 분기한다
- [ ] 챗·추출·메모리 LLM 호출이 해당 Tenant provider로 라우팅된다
- [ ] LLM Provider 변경이 재구축을 유발하지 않는다(임베딩 불변)
- [ ] `model_id`가 chat_model로 흡수되고 기존 chat 동작이 회귀 없이 유지된다
- [ ] dev는 키 없이 로컬 fake-llm으로 동작한다
- [ ] 테스트: ProviderResolver·키암호화는 결정적 단위, 라우팅은 Fake 경계로 호출 인자 검증
