# 98 — Operator access/refresh end-to-end

Status: ready-for-agent

## Parent

[PRD-admin-access-refresh-auth.md](../PRD-admin-access-refresh-auth.md) · [ADR-0013](../../../docs/adr/0013-admin-access-refresh-token-auth.md)

## What to build

Operator 로그인을 access/refresh 스킴으로 전환하는 첫 end-to-end 수직 슬라이스. 프론트의 공용 `authFetch` 래퍼를 여기서 최초 구축한다(99가 재사용).

백엔드: `POST /api/operator/auth/login`이 성공 시 body `{access_token}`(30분) + Set-Cookie(refresh, httpOnly·Secure·SameSite=Strict, Path를 refresh 엔드포인트로 한정). `POST /api/operator/auth/refresh`가 쿠키의 refresh를 읽어 회전(새 access + 새 refresh 쿠키), 쿠키없음/만료/폐기/재사용 시 401. access TTL을 30분으로 전환.

프론트: access를 **sessionStorage**에 보관(localStorage 제거). `authFetch`가 access를 부착하고, **401 시 1회 투명 refresh→원요청 재시도**, 앱 부팅 시 silent refresh로 access 복구. Operator 로그인/대시보드가 이 경로를 사용. 구 단일토큰(localStorage) 경로 제거(클린 컷오버).

## Acceptance criteria

- [ ] Operator 로그인이 access(body, 30분) + refresh(Set-Cookie, httpOnly·Secure·SameSite=Strict·경로한정) 반환
- [ ] `/api/operator/auth/refresh`가 쿠키 refresh로 새 access + 회전 쿠키 반환
- [ ] 쿠키 없음/만료/폐기/재사용 refresh → 401
- [ ] 프론트 access는 sessionStorage에만 저장(localStorage 미사용)
- [ ] `authFetch`: 401 시 투명 refresh 후 원요청 1회 재시도, 실패 시 로그인 화면 복귀
- [ ] 앱 부팅 시 silent refresh로 access 복구(쿠키 유효 시 재로그인 불필요)
- [ ] F5 시 sessionStorage의 유효 access 재사용(불필요한 재발급 없음)
- [ ] 구 Operator 단일토큰 localStorage 경로 제거
- [ ] 백엔드 엔드포인트 테스트(실DB) + 프론트 vitest(부팅 refresh·401 재시도)
