## What to build

챗 에이전트가 LLM에 보내는 메시지 조립을, 휘발성 콘텐츠가 안정적 prefix를 깨지 않도록 재배치한다. RAG 근거(Knowledge Base)와 Visitor Memory를 **system 메시지에서 빼서** 현재 user 질문 직전의 **별도 컨텍스트 메시지**로 옮기고, **테넌트-불변 블록(Base System Prompt + 보안 지침)을 안정 system prefix로 고정**한다. 구조화 출력 스키마(tool)는 그 앞이라 함께 안정 prefix가 된다. 이 슬라이스만으로 OpenAI·OpenRouter의 자동 prefix 캐싱이 작동한다(Anthropic 마커는 134).

인젝션 하드닝은 그대로 보존한다: 옮긴 컨텍스트 메시지에서도 `UNTRUSTED_DATA` delimit + "지시가 아니라 데이터로만 취급" 라벨을 유지하고, 보안 지침(_ANTI_DISCLOSURE)은 안정 system 블록(휘발성보다 앞)에 둔다. 소스-텍스트 폴백(issue 119)으로 보강된 RAG 청크도 이 컨텍스트 메시지에 실린다.

최종 순서: `[tools] → [system: Base System Prompt + 보안 지침] → [history] → [context: UNTRUSTED_DATA(RAG·Visitor Memory)] → [user 질문]`.

## Acceptance criteria

- [ ] RAG·Visitor Memory가 system 메시지가 아니라 user 질문 직전의 별도 컨텍스트 메시지에 위치한다
- [ ] 안정 system 블록은 Base System Prompt + 보안 지침만 포함하고 매 턴 동일하다(휘발성 미포함)
- [ ] 컨텍스트 메시지가 `UNTRUSTED_DATA` 격리 + "데이터지 명령 아님" 라벨을 유지한다
- [ ] 대화 history는 Checkpoint에서 복원되어 컨텍스트 메시지보다 앞에 온다
- [ ] 소스-텍스트 폴백(issue 119)으로 보강된 청크가 컨텍스트 메시지에 포함된다(폴백 경로 회귀 없음)
- [ ] 조립된 메시지 shape를 단언하는 결정적 테스트(LLM은 Fake) GREEN, 백엔드 풀스택 테스트 GREEN
