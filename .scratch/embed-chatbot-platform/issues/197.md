## What to build

주제범위 제어의 전 계층 관통 tracer bullet. 토글 ON + 범위 밖 질문이면 봇이 표준 문구로 거절하고,
인사·도메인 질문은 그대로 받는 핵심 경로를 chat 그래프에서 end-to-end로 잠근다.

- TenantConfig에 `topic_scope_enabled`(bool, 기본 False) + `scope_description`(text, 기본 "") 추가(마이그레이션).
- 구조화 출력(HITLResponse·PlainResponse)에 `in_scope` 제어필드 추가 — 제어필드(`in_scope`·
  `context_sufficient`)는 response보다 앞(스트리밍 선판정). 기본 True.
- 토글 ON일 때 `scope_description` 기반 스코프 지침 블록을 system prompt에 주입(deep module).
- scope 결정 deep module + 노드 백스톱: `topic_scope_enabled and not in_scope`이면 모델 response를
  무시하고 **표준 거절 메시지**(`scope_description` 인용)를 assistant 응답으로 확정. 스트리밍은
  in_scope=False면 억제 후 거절 발행.
- fail-open: 토글 ON인데 `scope_description`이 비면 OFF처럼 취급.
- HITL-on/off 두 경로(call_llm_structured/plain) 모두 적용.

## Acceptance criteria

- [x] 토글 ON + 범위 밖 질문(in_scope=False) → 표준 거절 발행, 모델의 off-topic 응답 미노출
- [x] 토글 ON + 인사·메타(in_scope=True) → 정상 응답(거절 안 함)
- [x] 토글 ON + 도메인 질문 in_scope=True → 정상 답변(거절 안 함)
- [x] 토글 OFF → 무엇이든 답함(현행 무변경)
- [x] 토글 ON + scope_description 비면 OFF처럼 동작(fail-open)
- [x] scope 결정 모듈·프롬프트 빌더 단위 테스트 + 노드 통합 테스트(fake LLM의 in_scope 제어), HITL-on/off
- [x] 전체 테스트 그린
