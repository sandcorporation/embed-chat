# 140 — POST /tenant/sessions/{id}/takeover : 임의 세션 상담 시작

Status: ready-for-agent

## Parent

[PRD-session-console-takeover-presence.md](../PRD-session-console-takeover-presence.md)

## What to build

상담원이 아무 세션이나 직접 상담을 시작하는 `POST /tenant/sessions/{session_id}/takeover`(tenant_agent_auth)를 만든다.

- **동작**: 자동-claimed `Escalation(trigger=agent, status=claimed, claimed_by=현재 agent)` 생성 + `session.is_hitl=True` + `publish_hitl_start`(방문자 "상담원 연결됨" 알림) + `publish_hitl_new`(콘솔 갱신). 응답으로 escalation id 반환(콘솔이 채팅 열기).
- **Escalation 모델 확장**: `TRIGGER_AGENT` 추가. claim/message/typing/resolve API는 그대로 재사용(takeover는 claim 단계 생략).
- **멱등**: 이미 active escalation이 있으면 그걸 반환(중복 생성 방지).
- **동시성**: 두 상담원이 동시 takeover하면 `EscalationClaim` OneToOne 유일성으로 한 명만 성공(409).
- **영업시간 무관 / 오프라인 허용**: `is_open`과 독립이며 presence와 무관하게 허용(메시지는 영속).
- 와이어 변경 → orval 재생성 + 커밋(ADR-0014).

## Acceptance criteria

- [ ] takeover가 자동-claimed Escalation(trigger=agent)을 만들고 is_hitl을 켜고 hitl_start를 publish한다
- [ ] 이미 active escalation이 있으면 새로 만들지 않고 기존 것을 반환(멱등)
- [ ] 동시 takeover는 한 명만 성공, 나머지는 409
- [ ] 영업시간 외·방문자 오프라인이어도 takeover 가능(메시지 영속)
- [ ] resolve 시 is_hitl=False로 AI 복귀(기존 흐름 재사용)
- [ ] orval 재생성 + 커밋, takeover·멱등·동시성을 실 DB+Redis로 검증하는 테스트 GREEN, 백엔드 풀스택 GREEN

## Blocked by
