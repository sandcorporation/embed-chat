## What to build

모든 이벤트 소비자가 공유하는 단일 파라미터화 consume 루프(management command `consume_events --group=<name>`)와 멱등·DLQ 기반을 만든다.

- consumer-group으로 스트림을 읽어 등록된 핸들러에 디스패치 → 성공 시 ack.
- **멱등**: `processed_events(consumer_group, event_id)` 유일키. 핸들러 처리 전 dedup 체크·삽입, 중복이면 스킵(ack만). DB 효과 있는 핸들러는 같은 트랜잭션에 dedup insert(사실상 exactly-once).
- **백오프/DLQ**: 핸들러 실패 시 XPENDING/XCLAIM idle로 제한 횟수 재시도 → 소진 시 dead-letter 스트림으로 이동 + 구조화 로그/알림.
- 핸들러 레지스트리: group 이름 → 핸들러 매핑(이후 소비자 슬라이스가 등록).

## Acceptance criteria

- [ ] `--group=` 인자로 해당 group의 핸들러만 구동된다
- [ ] 같은 event_id가 두 번 전달돼도 핸들러 효과는 1회(processed_events dedup)
- [ ] 핸들러가 N회 실패하면 dead-letter 스트림으로 이동하고 소비자는 멈추지 않는다
- [ ] 정상 처리 시 ack되어 재전달되지 않는다
- [ ] 실 Redis Streams+Postgres 기반 테스트 GREEN, 백엔드 풀스택 GREEN
