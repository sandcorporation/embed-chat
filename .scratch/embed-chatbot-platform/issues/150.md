Status: ready-for-agent

## Parent

## What to build

presence 전이를 EventBus ephemeral 스트림으로 옮기고(전송 일원화), presence-bridge 소비자가 이를 처리하게 한다. presence는 ephemeral·저위험이라 escalation 컷오버(151)와 **독립**으로 컷한다.

- SSE 라이프사이클(연결 시작/종료)이 기존 `publish_session_connected/disconnected`(직접 pub/sub) 대신 **`VisitorConnected`/`VisitorDisconnected`를 EventBus ephemeral 스트림(outbox 미경유, capped)에 발행**.
- **하트비트(keepalive `mark_active` ZADD)는 그대로 직접 Redis 쓰기 유지**(고빈도, 이벤트화 안 함).
- `presence-bridge` 소비자: ephemeral 이벤트 소비 → presence sorted-set 갱신 + `hitl:{tenant}`에 콘솔 델타 발행.
- 콘솔 스냅샷의 활성 판단은 여전히 presence sorted-set(`active_sessions`).

## Acceptance criteria

- [ ] SSE 연결/종료가 VisitorConnected/Disconnected를 EventBus ephemeral 스트림에 발행한다
- [ ] presence-bridge가 이를 소비해 sorted-set을 갱신하고 콘솔 델타를 발행한다
- [ ] 하트비트 ZADD는 직접 쓰기로 남아 TTL 자가치유가 보존된다(issue 138 동작 불변)
- [ ] 콘솔 활성 계층이 기존과 동일하게 동작한다(e2e)
- [ ] 직접 publish_session_* 경로 제거(단일 원천)
- [ ] 실 Redis 기반 테스트 + e2e GREEN, 백엔드 풀스택 GREEN
