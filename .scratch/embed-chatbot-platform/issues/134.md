# 134 — Anthropic cache_control 마커 (boundary, provider-aware)

Status: ready-for-agent

## Parent

[PRD-prompt-caching-restructure.md](../PRD-prompt-caching-restructure.md)

## What to build

LLM 호출 경계에서 **provider 타입이 anthropic일 때만** 안정 prefix 블록(133에서 고정한 system+tools)의 마지막 system 콘텐츠 블록에 `cache_control: {type: "ephemeral"}` 분기점 1개를 주입한다. OpenAI/custom/""(OpenRouter)은 마커 없이 자동 prefix 캐싱에 의존하므로 마커를 붙이지 않는다.

챗 노드는 논리적 메시지만 만들고(provider 분기 없음), 마커 주입 결정은 **boundary**가 호출 컨텍스트의 provider 타입을 보고 한다. provider는 이미 `get_chat_provider`로 흐른다.

스파이크: langchain `ChatAnthropic` + `with_structured_output`에서 콘텐츠를 블록 리스트로 줄 때 `cache_control`이 passthrough되는지 먼저 확인한다(안 되면 대안 경로 메모). Anthropic 최소 캐시 prefix(1024토큰 등) 미만이면 조용한 no-op이며 회귀로 보지 않는다.

## Acceptance criteria

- [ ] provider type==anthropic이면 안정 system 블록에 `cache_control` 마커가 1개 붙는다
- [ ] provider type이 openai/custom/""이면 마커가 붙지 않는다
- [ ] 마커 주입 로직은 boundary에 있고 챗 노드에는 provider 분기가 없다
- [ ] langchain ChatAnthropic passthrough 가능 여부를 스파이크로 확인하고 결과를 코드/주석에 반영
- [ ] provider별 마커 유무를 단언하는 결정적 테스트 GREEN, 백엔드 풀스택 테스트 GREEN
