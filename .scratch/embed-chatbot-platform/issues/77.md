# 배치 SAME_AS 동치 + Community 통합 (과소병합 해결)

## Parent

PRD: `.scratch/embed-chatbot-platform/PRD-entity-resolution.md` (ADR-0010)

## What to build

Community 재구축(배치) 시점에 EntityResolver로 동치를 계산해 **비파괴 SAME_AS 엣지**로 저장하고, 연결요소 탐지가 이를 연결로 소비하게 한다. 그 결과 같은 대상의 다른 표기가 같은 Community로 들어간다(과소병합 해결). 이 슬라이스에서는 name 기반 Entity 구조를 그대로 두고 그 위에 SAME_AS를 얹는다(동음이의 분리는 다음 슬라이스).

- `rebuild_communities`가 EntityResolver를 호출 → SAME_AS upsert(비파괴, 노드·표기·출처 보존).
- 연결요소 계산이 `RELATED` ∪ `SAME_AS`를 union → 동치로 묶인 노드가 같은 Community.
- Graph Freshness 흐름(stale→rebuilding→fresh)은 유지. tenant 스코프 유지.
- SAME_AS 조회/저장은 GraphStore 경계를 통한다.

## Acceptance criteria

- [ ] rebuild 후, 표기변이 두 노드(`FCB1010`/`FCB-1010`)가 SAME_AS로 연결되고 같은 Community에 속한다
- [ ] 특성화 테스트가 `synonym→2`에서 `synonym→1`로 전환된다(수용 기준)
- [ ] SAME_AS는 비파괴다 — 노드·표기·출처가 보존되고 엣지만 제거하면 되돌릴 수 있다
- [ ] 무관한 일반명으로 잘못 묶이지 않는다(보수적 정책이 rebuild 경로에서도 유지)
- [ ] rebuild 멱등성 — 동일 그래프 재구축 시 동일한 SAME_AS/Community 결과
- [ ] Graph Freshness 라이프사이클과 tenant 스코프가 유지된다
