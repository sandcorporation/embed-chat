# 세션 단위 직렬화 (Redis 락 + 재-enqueue)

## Parent

PRD: `.scratch/embed-chatbot-platform/PRD-chat-agent-celery.md`

## What to build

방문자가 메시지를 빠르게 두 번 보내 같은 `thread_id`(=session_id)로 두 태스크가 동시에 `graph.invoke`하면 PostgresSaver lost update·토큰 인터리빙이 발생한다(지금도 잠복, prefork+replica에서 악화). 세션 단위로 직렬화한다.

- **세션 락 deep module (신규).** `acquire(session_id) -> bool` / `release(session_id)`를 Redis `SETNX chat:lock:{session_id}` + TTL 위에 캡슐화한다. TTL은 하드 타임리밋(≈120s)으로 두어 크래시 시 세션이 영구 데드락되지 않게 한다. 외부 I/O는 Redis 하나뿐이라 결정적 단위 테스트가 가능한 deep module로 설계한다.
- **태스크 통합.** `run_chat_agent_task` 시작 시 락을 획득한다. 실패면 프로세스를 점유하지 말고 `apply_async(countdown=...)`로 **재-enqueue**해 두 번째 메시지가 첫 번째 뒤에 줄서게 한다. 종료 시 `try/finally`로 락을 해제하며, **예외 경로(`publish_error`)에서도 반드시 해제**해 다음 메시지가 막히지 않게 한다.

진짜 병렬 동시-세션 레이스는 비결정적이라 직접 테스트하지 않고, 락 모듈(T2)로 직렬화 메커니즘을 결정적으로 잠근다.

## Acceptance criteria

- [ ] 세션 락이 외부 의존 Redis만 갖는 deep module로 존재한다
- [ ] 같은 세션 2회 acquire → 두 번째가 False, release 후 재acquire가 True (T2)
- [ ] 락에 TTL이 있어 release 없이도 만료 후 재획득된다 (T2)
- [ ] 태스크가 락 미획득 시 에이전트를 실행하지 않고 재-enqueue한다(중복 assistant 메시지 없음)
- [ ] 태스크 정상 종료·예외 종료 모두에서 락이 해제된다(`try/finally`) (T3)
- [ ] 락 해제 실패 시에도 TTL로 자가치유된다
- [ ] 테스트: 실제 Redis로 락 모듈을 결정적으로 검증, `apps/agent/llm` 경계만 Fake. Prior art: `tests/test_hitl.py`, `tests/conftest.py`의 `redis_subscribe`
