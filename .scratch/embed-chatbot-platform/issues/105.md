# 105 — Auth mutator 딥모듈 + 단위테스트

## What to build

orval이 생성하는 모든 클라이언트 함수가 거치는 **custom mutator(custom instance)**. ADR-0013의 `authFetch` 로직을 흡수하되, 명시적 `kind` 인자 대신 **URL 프리픽스로 kind를 판정**한다.

인터페이스(개념): `customInstance<T>(config) => Promise<T>`
- URL이 `/api/operator/*` → operator, 그 외(`/api/tenant/*`) → agent
- 해당 kind의 sessionStorage access를 `Authorization`에 부착 + `credentials: 'include'`(refresh 쿠키)
- 401 시 `refresh(kind)` 후 **1회 재시도**, 실패 시 access 정리
- 2xx면 파싱된 `T` 반환, 재시도 후에도 non-2xx면 **throw**
- `auth.ts`의 `getAccess/refresh` 재사용

## Acceptance criteria

- [ ] mutator가 operator URL엔 operator access, agent URL엔 agent access를 Authorization에 싣는다(URL프리픽스 판정)
- [ ] 모든 요청에 `credentials: 'include'`
- [ ] 401 시 `refresh(kind)`→새 토큰으로 1회 재시도, 성공 시 데이터 반환
- [ ] refresh 실패 시 throw(+access 정리)
- [ ] 2xx 응답은 파싱된 데이터(T) 반환, 비-2xx(재시도 후)는 throw
- [ ] fake fetch로 위 동작 vitest 검증(생성 코드 없이 mutator 단독)
