## What to build

GraphStore에 Postgres+pgvector 백엔드를 도입하고, **TextUnit(원문) 벡터 저장·검색**을 그 위에서
동작시킨다. 개발 중 prod 안전을 위해 `GRAPH_BACKEND`(neo4j|pg, 기본 neo4j) 플래그로 게이팅 —
flag=pg일 때만 새 경로를 탄다(prod는 계속 neo4j). 공개 인터페이스는 불변.

- Django 마이그레이션: `CREATE EXTENSION IF NOT EXISTS vector` + 정적 공유 테이블(엣지·GraphMeta).
- 차원 라우팅 + 동적 DDL: 테넌트 `embed_dim`으로 `kg_text_unit_d{dim}` 테이블·HNSW를 `IF NOT EXISTS`로 생성(현 `ensure_vector_index` 패턴).
- 메서드(pg 경로): `ensure_vector_index`·`upsert_text_unit`·`query_text_units`·`all_text_units`·`set_text_unit_embedding`·`vector_search`·`set/get_freshness`. 모든 쿼리에 `tenant_id` 강제 주입.
- 검색은 테넌트 스코프(`WHERE tenant_id=$t ORDER BY embedding <=> $q`), iterative scan 활용.

## Acceptance criteria

- [ ] flag=pg에서 TextUnit upsert 후 `vector_search`가 최근접 원문을 반환한다(원문 폴백 시나리오 GREEN)
- [ ] 서로 다른 `embed_dim` 테넌트가 각자 차원 테이블에서 검색되고 결과가 섞이지 않는다
- [ ] 한 테넌트의 `vector_search`가 다른 테넌트의 벡터를 절대 반환하지 않는다(격리)
- [ ] 첫 인제스션이 테이블·HNSW를 IF NOT EXISTS로 멱등 생성한다
- [ ] flag=neo4j(기본)에선 기존 동작·테스트가 그대로 GREEN, 백엔드 풀스택 GREEN
