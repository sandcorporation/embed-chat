# 116 — update_config가 provider 저장 시 연결 검증 (실패 시 거부)

Status: ready-for-agent

## Parent

[PRD-provider-model-discovery.md](../PRD-provider-model-discovery.md) · [ADR-0012](../../../docs/adr/0012-per-tenant-llm-embedding-providers.md)

## What to build

broken provider가 저장되어 사용 시점에 조용히 실패하는 것을 막는다. config 저장 시 provider 필드가 바뀌었으면 114의 `validate_provider`로 연결을 검증하고, 실패하면 저장을 거부한다.

- `update_config`에서 LLM/Embedding provider 필드(type/base_url/key)가 **변경됐고 type이 non-empty**면 `validate_provider(kind, ...)` 호출.
- 검증 실패 시 PATCH **거부**(4xx + 에러), config는 저장되지 않음.
- provider 필드 **미변경 시 검증 생략**(provider 호출 안 함) — system_prompt 등만 바꿀 때 매번 provider를 치지 않게.
- 마스크 키(미변경)는 저장된 키로 검증.

## Acceptance criteria

- [ ] provider 필드 변경 + 유효 → 저장 성공
- [ ] provider 필드 변경 + 무효(키/URL 오류) → 4xx, config 미저장(롤백)
- [ ] provider 필드 미변경(예: system_prompt만 수정) → `validate_provider` 미호출, 저장 성공
- [ ] type이 비어있음(플랫폼 기본) → provider 검증 생략
- [ ] 마스크 키 그대로면 저장된 키로 검증(재입력 불필요)
- [ ] pytest: 변경+무효 거부 / 변경+유효 저장 / 미변경 시 검증 생략 (validate_provider는 Fake로 성공·실패 주입)
