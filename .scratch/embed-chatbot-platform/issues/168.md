## What to build

OpenAI API 키 하나로 3종 Provider(LLM·Embedding·OCR)를 기본 모델/차원으로 한 번에 설정하는 백엔드
경로. 핵심 로직은 테스트 가능한 deep module로, 노출은 전용 엔드포인트로.

- `POST /api/tenant/providers/quick-setup` `{api_key}`.
- 기본값(서버 상수): 챗=`gpt-4o-mini`, 추출=빈값(챗 폴백), 임베딩=`text-embedding-3-small`+`embed_dim=1536`, OCR=`gpt-4o-mini`. base_url 전부 빈값(openai 자동 보정).
- **키 1회 검증**(`list_provider_models`로 models 조회 — OpenAI 키는 chat/embed/vision 공통). 실패 시 400 + **아무것도 저장 안 됨**(원자성).
- 3종을 `type=openai` + 암호화 키로 저장. 임베딩 변경이라 reembed 트리거(신규 테넌트엔 no-op).
- OpenAPI 변경 → `bash scripts/gen-admin-api.sh`로 orval 재생성, generated 함께 커밋(ADR-0014).

## Acceptance criteria

- [ ] 유효 키로 호출 시 3종이 openai로 저장되고 모델·dim(1536)이 기본값으로 채워진다
- [ ] 키 검증 실패 시 400이고 config는 변경되지 않는다(원자성)
- [ ] 키 검증은 1회만 호출된다(중복 없음)
- [ ] 저장 키는 암호화되고 GET 응답에선 마스킹된다
- [ ] orval 재생성분(openapi.json·generated) 커밋, 드리프트 훅 통과
- [ ] provider HTTP를 Fake한 백엔드 테스트 GREEN, 백엔드 풀스택 GREEN
