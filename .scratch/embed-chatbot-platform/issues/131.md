## What to build

ConfigTab의 긴 단일 폼을 **세부 탭 4개**로 그룹핑한다. 단일 폼·atomic 저장은 유지(컴포넌트 내부 탭 상태, 라우트 분리 안 함).

- 세부 탭: **일반**(브랜드·환영 메시지·시스템 프롬프트·상담원 이름) · **AI 모델**(LLM/Embedding Provider 일체) · **상담 전환(HITL)**(HITL 토글·웹훅) · **공개 URL·보안**(Slug·신원검증·API KEY 재발급).
- 활성 탭의 필드만 렌더. **"저장" 버튼은 항상 보이며 전체 config를 atomic 저장**(Slug 저장·키 재발급은 별도 액션 유지).
- 활성 탭을 `?section=general|ai|handoff|security`에 동기화(`useSearchParams`), 진입 시 쿼리로 초기 탭 결정.
- 모든 aria-label·data-testid·저장/조회·provider 검증·base_url custom 게이팅·고급 설정 동작 보존.

## Acceptance criteria

- [ ] 4개 세부 탭 노출, 기본=일반. 탭 전환 시 해당 그룹 필드만 보임
- [ ] "저장" 버튼이 탭과 무관하게 항상 보이고, 한 탭에서 입력 후 다른 탭으로 가도 값 보존되어 **저장 payload에 양쪽 포함**(atomic)
- [ ] `?section=ai` 등으로 진입 시 해당 세부 탭이 활성, 탭 전환 시 URL 갱신
- [ ] Slug 저장·API KEY 재발급·provider 검증·모델 불러오기·base_url custom·고급 설정 전부 정상
- [ ] 기존 `ConfigTab.test.tsx` 케이스를 **대상 세부 탭 이동 후 조작**으로 갱신 → 전부 GREEN
- [ ] 신규 테스트: 탭 전환 노출/비노출, `?section=` 딥링크, 탭 오간 뒤 atomic 저장
- [ ] admin vitest·tsc·build GREEN
