## What to build

챗 답변을 토큰별로 흘리는 핵심 경로(HITL-on). LLM 단일 호출을 스트리밍으로 바꿔 `response` 델타를
실시간 publish하되, 구조화 출력의 폴백 라우팅과 충돌하지 않게 한다.

- 경계 `stream_structured(provider, messages, schema)`: `with_structured_output(schema).stream()`로 **누적 dict**를 점진 yield(아직 안 온 필드는 키 부재 — Pydantic 기본값 함정 회피). `complete_structured`(추출용)는 유지.
- 스키마 필드 순서 **제어필드 먼저**: `HITLResponse` = `context_sufficient` → `response` → `needs_hitl` → `hitl_reason`.
- `call_llm_structured`: 스트림 소비 → `'context_sufficient' in d`로 종단 판정(`_will_source_fallback`) → 종단이면 `response` 델타를 `publish_token`, 폴백이면 억제. 끝에 dict를 schema 검증해 라우팅 값 반환 + `publish_done`.
- **우아한 자동 저하**: 제어필드가 response보다 늦거나 부분 스트리밍이 없으면(최종 1청크) 버퍼링 → 종단이면 **끝에 한 번 publish**(현행 one-shot), 폴백이면 억제. 절대 중복·후퇴 없음.
- conftest `_FakeChatLLM`에 `stream_structured` Fake 추가(제어 dict → response 청크 결정적 yield).

## Acceptance criteria

- [ ] 종단 패스에서 `publish_token`이 여러 번(델타) 호출되고 누적이 최종 응답과 일치
- [ ] 폴백 패스(context_sufficient=False·미시도)에선 스트리밍 억제(중복 출력 0 — issue 119 회귀 보존)
- [ ] 제어필드가 늦게 오는 Fake에선 끝에 one-shot으로 저하(깨짐·중복 없음)
- [ ] 라우팅(needs_hitl·context_sufficient)·HITL 전환 멘트 스트리밍 정상, checkpoint 보존
- [ ] stream_structured 경계 + 노드 테스트 GREEN, 백엔드 풀스택 GREEN
