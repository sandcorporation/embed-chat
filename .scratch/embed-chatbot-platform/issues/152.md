## What to build

dead-letter로 떨어진 이벤트를 운영자가 조회·재처리하는 management command와 간단한 운영 문서를 만든다.

- `events_dlq list`: dead-letter 스트림의 항목(이벤트 type·aggregate_id·실패 사유·시각)을 조회.
- `events_dlq replay <id|all|--group=>`: 선택 항목을 원 스트림(또는 핸들러)로 되돌려 재처리. 멱등(processed_events)이 있어 안전.
- 자동 재처리 루프는 만들지 않는다(poison 폭풍 방지) — 운영자 트리거 전용.
- 운영 문서: dead-letter 발생 시 조회→원인 수정→리플레이 절차(README 또는 docs).

## Acceptance criteria

- [ ] dead-letter 항목을 조회하는 CLI가 동작한다
- [ ] 선택/전체 리플레이가 원 핸들러로 재처리되고 멱등으로 이중효과 없음
- [ ] 자동 재처리 루프 없음(수동 트리거만)
- [ ] 운영 절차 문서화
- [ ] 실 Redis 기반 테스트 GREEN, 백엔드 풀스택 GREEN
