## What to build

admin의 9개 컴포넌트 + 페이지를 `.tsx`로 전환하고, 손작성 CRUD 호출을 **생성 클라이언트 함수**로 교체한다. 손작성으로 남는 것은 `login/refresh/logout`(부수효과)와 `openEscalationStream`(SSE)뿐 — 이를 생성 클라이언트와 공존하도록 정리한다. 기존 프론트 테스트를 새 구조에 맞게 재배치한다.

- 호출 계약 변경: 생성 함수는 데이터 반환·throw → 호출부의 `res.json()`/`res.ok` 패턴 정리.
- 테스트 재배치: 컴포넌트 테스트는 **생성 모듈을 mock**(`ConfigTab.test` 등). mutator/401-재시도 테스트는 105로, 손작성 auth/SSE 테스트(`api.logout`/`api.stream`)는 유지·TS화.

## Acceptance criteria

- [ ] 9개 컴포넌트 + 페이지가 `.tsx`로 전환되고 생성 클라이언트를 호출(손작성 CRUD 제거)
- [ ] 손작성 잔존은 login/refresh/logout + openEscalationStream 뿐, 생성 클라이언트와 공존
- [ ] 호출부가 데이터 반환·throw 계약에 맞게 정리(Response 직접 핸들링 제거)
- [ ] ConfigTab 등 컴포넌트 테스트가 생성 모듈 mock으로 동작(UI·payload 검증)
- [ ] 손작성 auth/SSE 테스트(logout 3종·SSE 재오픈) 유지·GREEN
- [ ] admin 전체 vitest GREEN(docker), 타입 컴파일 통과
- [ ] Operator·TenantAgent 대시보드 전 화면이 회귀 없이 동작
