## What to build

무한 루프를 직접 도는 관리 명령(`run_relay`·`run_consumer`)만 컨테이너 사망 위험이 있었다 —
부팅 sweep의 `drain_once`·`process_once`에 가드가 없어, 인프라 오류(Redis/DB 단절, events
마이그레이션 미적용 등)에 프로세스째 종료돼 크래시루프에 빠졌다. 두 루프를 supervisor 패턴으로
감싸 오류 시 로그+backoff 후 재구독/재구성해 재시도한다(컨테이너 생존, 의존성 복구 시 자가 회복).
api(gunicorn)·celery worker는 설계상 이미 복원력이 있어 대상 아님.

## Acceptance criteria

- [x] `run_consumer`가 일시 `process_once` 예외에 죽지 않고 재시도로 계속 돈다
- [x] `run_relay`가 부팅 sweep 예외에도 죽지 않고 루프를 지속(재연결 시 catch-up sweep)
- [x] 부팅 sweep은 stop과 무관하게 1회 보존(기존 의미 유지)
- [x] 기존 relay/consumer/command 테스트 회귀 없음, 백엔드 풀스택 GREEN
