## What to build

Knowledge Graph 인스펙터를 받쳐줄 검색/이웃 조회를 백엔드에 추가하고, 폐기되는 RAG 검색 엔드포인트를 제거한다.

- GraphStore(둘 다 tenant 스코프): `search_entities(term)`(이름/설명 부분일치 → 엔티티 목록), `neighbors(name)`(엔티티 + 1홉 이웃 + 관계를 `{nodes, edges}`로).
- API: `GET /rag/graph/search?q=<term>` → 매칭 엔티티 + 각 1홉을 합친 `{nodes, edges}`. `GET /rag/graph/neighbors?entity=<name>` → 1홉 `{nodes, edges}`. nodes=`{name,type,description,source_document_ids}`, edges=`{source,target,description}`.
- 폐기: `POST /rag/query` 엔드포인트 제거(`vector_search`는 chat local_search가 쓰므로 유지). 폐기 후 chat 검색·기타 동작 무영향.

## Acceptance criteria

- [ ] `search_entities`가 이름/설명에 매칭된 엔티티를 반환하고 tenant 격리된다
- [ ] `neighbors`가 엔티티 + 1홉 이웃·관계를 `{nodes, edges}`로 반환한다
- [ ] `/rag/graph/search`·`/rag/graph/neighbors`가 계약대로 `{nodes, edges}`를 반환하고 tenant 격리된다
- [ ] `/rag/query`가 제거되고, chat의 local/global 검색은 그대로 동작한다
- [ ] 실제 Neo4j로 검증(결정적)
