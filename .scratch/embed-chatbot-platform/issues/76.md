# EntityResolver deep module — 보수적 임베딩 동치 클러스터링

## Parent

PRD: `.scratch/embed-chatbot-platform/PRD-entity-resolution.md` (ADR-0010)

## What to build

임베딩을 가진 Entity Mention 집합을 입력받아 **보수적 동치 쌍(SAME_AS 후보)**을 산출하는 순수·결정적 deep module. 이번 슬라이스는 로직만 만들고 그래프에 연결하지 않는다(아무 동작도 깨뜨리지 않음).

- 인터페이스: "Mention(+embedding) 집합 → 동치 쌍/클러스터". 외부 I/O 없이 격리 단위 테스트가 가능해야 한다.
- 신호: 임베딩(name+description) 코사인 유사도. 정체성은 이름이 아니라 맥락이므로 설명이 반영된 임베딩을 쓴다.
- 정책: **보수적** — 위험이 비대칭(과대병합이 과소병합보다 해롭다)이므로 강하게 정합할 때만 동치로 묶고 애매하면 분리를 유지한다. 임계·정책은 모듈 내부에 캡슐화하고 fixture로 튜닝한다.
- tenant 스코프 입력만 받는다(테넌트 간 동치 금지). LLM은 쓰지 않는다.

## Acceptance criteria

- [ ] 외부 의존 없는 결정적 모듈로 존재하며 DB 없이 단위 테스트된다
- [ ] 표기변이 쌍(예: `FCB1010`/`FCB-1010`, 설명 맥락 동일)이 동치로 묶인다
- [ ] 동음이의(예: `다리`+"한강 대교 설명" vs `다리`+"신체 부위 부상 설명")는 설명 임베딩 차이로 분리된다
- [ ] 맥락도 가까운 근접 다른 대상(`Pedal A`/`Pedal B`)은 보수적으로 분리된다
- [ ] 같은 입력에 대해 멱등(재실행 시 동일한 동치 집합)이다
- [ ] tenant가 다른 Mention은 절대 동치로 묶이지 않는다(스코프 입력으로 구조적 보장)
