## What to build

chat 그래프의 구조화 LLM 호출(`HITLResponse`)을 단일 경계 함수 뒤로 캡슐화하고, 단위/통합 테스트에서 그 경계를 결정적 Fake로 교체한다. 결과적으로 HITL/escalation/checkpoint 테스트가 실제 qwen 호출 없이 결정적으로 통과한다.

- 신설 LLM 경계 모듈에 `complete_structured(model_id, messages, schema)`를 둔다. 프로덕션 구현은 기존과 동일하게 `OPEN_ROUTER_*`로 `ChatOpenAI(...).with_structured_output(schema).invoke(messages)`.
- chat 그래프의 구조화 호출 노드가 이 경계를 **모듈 속성으로** 호출한다(테스트에서 교체 가능하도록). 토큰 발행·상태 갱신 등 기존 로직은 유지.
- 테스트 autouse fixture가 경계를 Fake로 교체: 메시지에 인간 상담원 키워드(`상담원`)가 있으면 `needs_hitl=True`, 아니면 카난 응답 + `needs_hitl=False`.
- 기존 LLM 의존 테스트(escalation 생성, 비-escalation 저장, `hitl_start` SSE, resolved 후 재개, agent가 만든 escalation 웹훅, checkpoint 조회/누적)를 Fake 기반으로 결정화.

## Acceptance criteria

- [ ] chat 그래프 구조화 호출이 신설 경계 함수를 통해 이뤄지고, 노드 내 `ChatOpenAI` 직접 생성이 제거된다
- [ ] autouse Fake가 적용되어 "상담원" 포함 메시지는 Escalation 생성·`is_hitl=True`·`hitl_start` SSE를 트리거한다
- [ ] 일반 메시지는 `needs_hitl=False`로 assistant 메시지가 저장된다
- [ ] `test_hitl.py`·`test_webhook.py`(run_chat_agent 경로)·`test_chat_session.py`(checkpoint)가 실제 LLM 없이 통과한다
- [ ] 전체 백엔드 스위트를 여러 번 실행해도 해당 테스트들이 결정적으로 통과한다
- [ ] 프로덕션 LLM 동작은 변경되지 않는다
