# 32 — Memory 버그 수정

Status: ready-for-agent

## Parent

`.scratch/embed-chatbot-platform/PRD-conversation-visibility.md`

## What to build

두 가지 버그를 수정한다. (1) `DELETE /api/tenant/visitors/{visitor_id}/memory/{memory_id}` 엔드포인트가 response 스키마에 404가 누락돼 Ninja ConfigError가 발생함 → `{204: None, 404: dict}`로 수정. (2) `schedule_memory_extraction` Celery 태스크가 LLM 응답에서 JSON을 파싱할 때 코드 펜스(` ```json ... ``` `)를 처리하지 못해 조용히 실패함 → 코드 펜스를 제거한 뒤 파싱. 또한 `session.tenant` FK가 없어 항상 default 모델을 사용하는 문제도 수정 (`TenantConfig`를 직접 조회).

## Acceptance criteria

- [ ] 존재하지 않는 memory_id로 DELETE 요청 시 404 반환
- [ ] LLM이 코드 펜스로 감싼 JSON을 반환해도 Memory가 정상 저장됨
- [ ] memory extraction이 Tenant의 `model_id`를 사용함
