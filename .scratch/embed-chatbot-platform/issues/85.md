# Slug 기반 연결 — EmbedToken 폐지 (tracer)

## Parent

PRD: `.scratch/embed-chatbot-platform/PRD-public-slug-access.md` (ADR-0011)

## What to build

EmbedToken을 폐지하고 `/chatbot/{slug}/` 공개 URL로 Visitor가 바로 연결되게 한다. 발급 왕복 없이 Tenant는 iframe만 박는다. 이 슬라이스가 새 접근 모델의 tracer다.

- **연결 계약**: stream이 `?token=` 대신 `slug`(경로) + `visitor_id`(쿼리)를 받아 → slug로 Tenant 조회 → `get_or_create ChatSession(tenant, visitor_id)` → SSE. message POST는 기존대로 session_id.
- **Anonymous Visitor ID**: 위젯이 `?visitor_id=` 미제공 시 추측 불가한 랜덤 id를 생성·localStorage 저장·재사용(세션 넘어 지속). 위젯은 slug를 URL 경로에서 읽고 `?token=` 분기를 제거.
- **clean cut**: `create/verify_embed_token`, 발급 엔드포인트, TTL 설정 제거(공존 없음).
- **VisitorContext 폐지**: `ChatSession.visitor_context` 컬럼 드롭 + 프롬프트의 "## Visitor Context" 주입 제거.

## Acceptance criteria

- [ ] `/chatbot/{slug}/?visitor_id=x`로 연결 시 토큰 없이 chat이 동작하고 assistant 응답이 저장된다
- [ ] visitor_id 미제공 시 위젯이 Anonymous Visitor ID를 생성·저장하고, 같은 브라우저 재방문 시 동일 세션·이력이 복원된다
- [ ] 위젯이 slug를 URL 경로에서 읽고 `?token=` 분기가 제거됐다
- [ ] EmbedToken 발급/검증/엔드포인트/TTL이 제거됐다(잔재 없음)
- [ ] `ChatSession.visitor_context`가 드롭되고 프롬프트 조립에 Visitor Context 블록이 없다
- [ ] visitor_context 없이 chat이 정상 동작한다
- [ ] 기존 chat 동작(is_hitl 차단, 체크포인트 등) 회귀 유지
- [ ] 테스트: slug+visitor_id 연결·익명 재방문·VisitorContext 제거를 실제 Redis·DB·SSE로 통합 검증, LLM 경계만 Fake
