# Chat 에이전트를 Celery 태스크로 (gevent 스레드 제거)

## Parent

PRD: `.scratch/embed-chatbot-platform/PRD-chat-agent-celery.md`

## What to build

Tracer bullet — 에이전트 실행을 gevent greenlet에서 Celery 태스크로 옮기는 핵심 경로를 end-to-end로 잠근다. 이 슬라이스만으로도 (큐를 공유하는 기존 워커에서) chat이 프로세스 격리되어 web 워커의 hub를 더 이상 얼리지 않는다.

- **`run_chat_agent_task(session_id, user_message)` 신규 Celery 태스크.** 기존 `run_chat_agent`(LangGraph `graph.invoke` 전체)를 통째로 감싸는 얇은 래퍼. `session_id`(str)만 받아 내부에서 `ChatSession`을 재조회한다(`CELERY_TASK_SERIALIZER="json"`이라 ORM 객체 직렬화 불가). 노드 분해는 하지 않는다 — LangGraph가 이미 오케스트레이션한다.
- **at-most-once 태스크 설정.** `max_retries=0`, `autoretry_for` 미설정, `acks_late=False`. 스트리밍은 이미 나간 토큰을 회수할 수 없어 비멱등이므로 재시도·재배달은 토큰/과금/메시지 중복을 부른다.
- **예외 처리.** 태스크 내부에서 예외를 잡아 `publish_error(session_id, ...)`로 사용자에게 알린다(현재 뷰의 `_run_agent` except 동작과 동일).
- **뷰 교체.** `POST /chat/message`의 non-hitl 분기에서 `threading.Thread(target=_run_agent, ...)`를 `run_chat_agent_task.delay(str(session.id), content)`로 **완전 대체**한다. 토글 플래그를 두지 않는다. `is_hitl` 분기(`publish_visitor_message`)는 불변.

토큰 전달은 이미 Redis pub/sub로 디커플링되어 있어 태스크가 스레드와 동일하게 `publish_token`하면 SSE 경로는 그대로 동작한다. 세션 단위 직렬화(락)와 전용 큐 격리는 후속 슬라이스(83, 82)에서 얹는다 — 이 슬라이스는 기본 큐로도 데모 가능하다.

## Acceptance criteria

- [ ] `run_chat_agent_task`가 Celery 태스크로 존재하고 `session_id`·`user_message`만으로 호출된다(ORM 객체 미전달)
- [ ] non-hitl `POST /api/chat/message` 후 `CELERY_TASK_ALWAYS_EAGER`로 태스크가 인라인 실행되어 assistant `ChatMessage`가 저장된다 (T1)
- [ ] 태스크 데코레이터가 at-most-once다: 자동 재시도 없음, `acks_late=False`
- [ ] 에이전트 실행 중 예외 시 `publish_error`가 Redis에 발행된다 (T3 일부)
- [ ] 옛 `threading.Thread`/`_run_agent` 경로가 제거되고 토글 플래그가 없다
- [ ] `is_hitl=True` 세션은 여전히 에이전트를 깨우지 않는다(기존 `test_hitl_mode_session_does_not_invoke_agent` 회귀 유지)
- [ ] `run_chat_agent`를 직접 호출하는 기존 hitl/graph 테스트가 변경 없이 통과한다
- [ ] 테스트: 실제 Redis·DB, `apps/agent/llm` 경계만 Fake. Prior art: `tests/conftest.py`의 `celery_always_eager`/`fake_chat_llm`/`redis_subscribe`, `tests/test_hitl.py`
