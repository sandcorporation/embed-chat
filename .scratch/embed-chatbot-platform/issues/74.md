# 깨진 PDF 추출(Garbled Extraction) 감지 → OCR 재추출

## Parent

PRD: `.scratch/embed-chatbot-platform/PRD-garbled-pdf-ocr-fallback.md`

## What to build

텍스트 레이어의 폰트 인코딩이 깨져 mojibake(예: `-%&././ 2*$* … PRG CHG 1`)로 추출되는 PDF를, 추출 직후 감지해 OCR로 문서 전체를 재추출한다.

- **깨짐 감지 deep module (신규)**: `apps/rag/`에 외부 의존이 없는 순수 함수 `is_garbled(text: str) -> bool`. 문자 클래스 비율 휴리스틱을 캡슐화한다 — 전체 비공백 문자 대비 의미 있는 letter(한글 음절 + 라틴 letter) 비율이 낮고 기호·단일문자 토큰 비율이 높으면 깨짐으로 판정. 임계값은 모듈 내부 상수로 두고 fixture로 튜닝. 이 모듈은 슬라이스 2(청크 드롭)에서도 공유한다.
- **PDFIngester 폴백 확장**: 기존 단어 수 조건 옆에 OR로 깨짐 감지를 추가한다. 추출 텍스트가 `단어 수 부족` 또는 `is_garbled`이면 기존 `_ocr_pdf`로 문서 전체를 재추출. 폴백 단위는 문서 전체(페이지 단위 폴백은 채택하지 않음).

OCR은 픽셀에서 글자를 다시 읽어 폰트 인코딩 깨짐과 무관하게 진짜 텍스트를 되찾는다. LLM 정제·복원은 쓰지 않는다(ADR-0009). 감지 신호로 U+FFFD 카운트는 쓰지 않는다 — fcb1010은 잘못된 ASCII로 매핑되어 안 잡히기 때문.

## Acceptance criteria

- [ ] `is_garbled(text)`가 독립 모듈의 순수 함수로 존재하고 외부 의존이 없다
- [ ] fcb1010 실제 발췌(`-%&././ 2*$* …`)에 대해 `is_garbled`가 True를 반환한다
- [ ] 정상 한글/영어 텍스트, 그리고 기호가 많은 정상 텍스트(코드·표)에 대해 False를 반환한다(오탐 경계 케이스 포함)
- [ ] 텍스트 레이어가 mojibake인 PDF를 업로드하면 OCR 재추출이 트리거되어 Text Unit content가 정상 텍스트로 저장된다
- [ ] 텍스트 레이어=mojibake(invisible)·이미지 픽셀=정상 텍스트인 fixture로 감지와 OCR 복원을 한 통합 테스트에서 검증한다
- [ ] 단어 수가 충분한 정상 PDF는 OCR을 건너뛴다(기존 `test_pdf_normal_text_skips_ocr` 회귀 유지)
- [ ] 텍스트 레이어가 희소한 스캔 PDF는 기존대로 OCR 폴백한다(기존 `test_pdf_ocr_fallback_used_when_text_too_sparse` 회귀 유지)
- [ ] Document status가 garble→OCR 경로를 통과해도 ready/failed로 올바르게 설정된다
- [ ] TXT/이미지 인제스션 경로는 변경되지 않는다
- [ ] 테스트: `is_garbled` 단위 테스트는 DB 불필요(순수 함수), 통합 테스트는 임베딩·Neo4j·OCR(paddle) 실제 객체 + `apps/agent/llm` 경계만 Fake. Prior art: `tests/test_rag.py`의 "Issue 50: PDF OCR Fallback" 섹션(`_make_image_only_pdf`)
