## What to build

E2E 스택의 chat LLM을 결정적 Fake LLM 서비스로 교체해, HITL escalation E2E 흐름이 실제 qwen 없이 결정적으로 통과하게 한다.

- OpenAI Chat Completions 호환 HTTP 서비스(신설 컨테이너)를 만든다. 요청에 `tools`/`tool_choice`가 있으면(langchain `with_structured_output`의 function_calling) tool_call로 스키마 JSON을 반환한다. 마지막 사용자(role=user) 메시지에 인간 상담원 키워드(`상담원`)가 있으면 `needs_hitl=true`(빈 response + 사유), 없으면 `needs_hitl=false` + 카난 한국어 응답. system 프롬프트는 판정에서 제외. 정확한 tool_call 응답 형식은 langchain-openai 0.2.x의 실제 요청을 1회 로깅해 확정한다.
- 이 서비스를 `docker-compose.test.yml`에 추가(healthcheck 포함)하고, `api-e2e`/`worker-e2e`의 `OPEN_ROUTER_BASE_URL`을 Fake(`http://<svc>:<port>/v1`)로 변경한다. 임베딩(`OLLAMA_BASE_URL`, bge-m3)은 변경하지 않는다.
- `hitl.spec.js`가 결정적으로 통과한다: 방문자가 "상담원" 요청 → 위젯에 HITL 시작 메시지, 어드민이 pending escalation을 claim/resolve. 각 테스트는 자체 세션을 만들어 독립적이다.

## Acceptance criteria

- [ ] Fake LLM 서비스가 `/v1/chat/completions`에서 구조화(tool_call) 요청에 `needs_hitl` 판정 JSON을 반환한다
- [ ] "상담원" 포함 사용자 메시지 → `needs_hitl=true`, 미포함 → `needs_hitl=false` (system 프롬프트 무관)
- [ ] `api-e2e`/`worker-e2e`가 Fake LLM을 사용하도록 배선되고 컨테이너가 healthy
- [ ] `hitl.spec.js`가 fresh-session 재시도 없이(단일 escalation) 결정적으로 통과한다
- [ ] `hitl.spec.js`를 여러 번 실행해도 항상 통과한다
- [ ] 임베딩/프로덕션 LLM 동작은 변경되지 않는다
