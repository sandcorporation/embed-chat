# Issue 59: Checkpoint에서 lc_messages 채널 제거 (노드 병합)

Status: ready-for-agent
Labels: ready-for-agent

## Parent

PRD: `.scratch/embed-chatbot-platform/PRD-checkpoint-lc-messages.md`

## What to build

chat agent 그래프에서 `lc_messages`를 영속 상태 채널에서 제거해, LangGraph Checkpoint에 대화가 `messages` 하나로만 남게 한다. 이로써 어드민 Checkpoint 뷰의 중복(LangChain 객체 형태 + dict 형태) 및 시간순 아님 현상이 사라진다.

- 프롬프트 조립(`assemble_prompt`)과 LLM 호출(`call_llm`) 노드를 하나로 병합한다. 병합 노드가 system 프롬프트 + Visitor Context/Memory + RAG chunks + 과거 `messages` + 현재 `user_message`로 LangChain 메시지 리스트를 **로컬 변수**로 조립해 곧바로 LLM 경계를 호출한다. `lc_messages`는 반환/저장하지 않는다.
- `ChatState`에서 `lc_messages` 필드를 제거하고 그래프 엣지를 `retrieve → call_llm → (route)`로 정리한다.
- 외부 동작(assistant 응답, 토큰 스트리밍, HITL escalation 라우팅, 메시지 누적/저장)은 동일하게 유지한다.
- 기존 세션 마이그레이션은 하지 않는다(앞으로만 수정). orphan `lc_messages`가 다음 턴에서 새 snapshot에 실리지 않는지 확인한다.

## Acceptance criteria

- [ ] 한 턴 실행 후 Checkpoint `channel_values`에 `messages`는 존재하고 `lc_messages` 키는 없다
- [ ] Checkpoint의 `messages`가 시간순([user, assistant, ...])이며 중복이 없다
- [ ] 기존 HITL/checkpoint 테스트(escalation 생성, 비-escalation assistant 저장, checkpoint 누적, resolved 후 재개)가 그대로 통과한다
- [ ] 멀티턴 대화의 assistant 응답·HITL 동작이 변경 전과 동일하다
- [ ] 회귀 테스트가 "lc_messages 부재 + messages 시간순"을 잠근다
