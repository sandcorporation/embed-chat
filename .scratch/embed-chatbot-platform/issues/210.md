## What to build

Tenant Admin이 팀원의 역할을 바꾸고, 조직이 절대 lockout되지 않게 하며, 어드민 UI가 역할에 맞춰 보이게 한다.

- 역할 변경 엔드포인트(`agents.manage` 가드): 팀원을 Admin↔Member로 승격/강등.
- last-admin 가드: 대상 변경(비활성화 또는 강등)이 "활성 Admin 0명"을 만들면 거부. 비활성화·강등 양쪽.
  (활성 Admin이 0이 되는 사고는 TENANT_KEY break-glass로만 복구 — 208에서 보장.)
- 어드민 UI: 팀원 탭에 각 팀원의 역할 표시 + 역할 변경(승격/강등) 컨트롤, 마지막 Admin 보호(거부 시 안내).
  토큰의 역할로 **Member에게 Admin 전용 컨트롤(reset-key·Slug 변경 등)을 숨기거나 비활성**.

## Acceptance criteria

- [ ] Admin이 팀원을 Admin↔Member로 변경할 수 있다(Member는 이 동작 403)
- [ ] 마지막 활성 Admin의 비활성화·강등은 거부된다(Admin 2명 이상일 땐 허용)
- [ ] 팀원 탭에서 역할이 보이고 변경되며, 마지막 Admin 보호가 UX로 드러난다
- [ ] Member로 로그인하면 reset-key·Slug 변경 등 Admin 전용 컨트롤이 숨김/비활성된다
- [ ] 역할 변경·last-admin 가드 백엔드 테스트 + 팀원 탭/게이팅 vitest 그린
