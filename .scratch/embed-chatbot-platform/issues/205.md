## What to build

Langfuse에서 테넌트별 필터·세션 그룹을 metadata 검색이 아니라 **1급 차원**(태그·native sessionId)으로
볼 수 있게 한다. 현재 tenant_id는 metadata에만 있고 native userId/sessionId/tags는 비어 있다.

- LLM 경로(_usage_config)와 임베딩 경로(203) 트레이스에 공통으로:
  - **tenant 태그**(예: `tenant:{slug}` 또는 `tenant:{id}`) — Langfuse 태그 드롭다운/대시보드 세그먼트.
  - **native sessionId** = ChatSession id — 대화 단위 그룹(metadata.session_id를 native로 승격).
  - (선택) native userId = visitor_id.
- langchain 연동은 config metadata의 `langfuse_tags`·`langfuse_session_id`(필요 시 `langfuse_user_id`)
  키를 native 필드로 매핑한다. 임베딩(수동 generation)도 동일 tenant 태그를 단다.
- 테넌트 식별값(slug/id)을 일관된 헬퍼로 만들어 LLM·임베딩이 공유한다.

## Acceptance criteria

- [ ] chat LLM 트레이스에 tenant 태그 + native sessionId가 붙는다
- [ ] 임베딩 generation에도 동일 tenant 태그가 붙는다
- [ ] Langfuse에서 tenant 태그로 필터 시 그 테넌트 트레이스만 보인다(수동 확인 가능)
- [ ] 태그/세션 매핑 단위 테스트(metadata 키가 올바르게 구성됨), Langfuse는 Fake
- [ ] 전체 테스트 그린

## Blocked by
