## What to build

HITL escalation 라이프사이클의 생산 지점을 한 번에 이벤트 발행으로 컷오버한다(빅뱅). 직접 사이드이펙트(webhook `.delay`, `publish_hitl_*`)를 제거하고, 소비자(webhook·visitor-bridge·console-bridge)를 **유일 경로**로 만든다.

- 네 전이를 `transaction.atomic` 안에서 상태 변경 + `record_event`로 발행:
  - `create_escalation_node`(AI escalation, LangGraph/worker-chat) → `SessionEscalated`.
  - claim 엔드포인트 → `EscalationClaimed`.
  - takeover 엔드포인트 → `SessionTakenOver`.
  - resolve 엔드포인트 → `EscalationResolved`.
- 기존 직접 호출 제거: `dispatch_webhook_task.delay`, `publish_hitl_start/new/end`(이제 소비자가 발행).
- **parity 테스트가 머지 게이트**: 컷오버 후 방문자 SSE·콘솔 델타·webhook 발사의 관찰 결과가 컷오버 전과 동일함을 단위+통합+e2e로 증명.

## Acceptance criteria

- [ ] 네 전이가 각각 정확히 1건의 올바른 도메인 이벤트를 event_store/outbox에 원자적으로 남긴다(상태 롤백 시 이벤트도 없음)
- [ ] 직접 webhook `.delay`·`publish_hitl_*` 호출이 코드에서 제거된다
- [ ] AI escalation → webhook 1회 + 방문자 hitl_start + 콘솔 델타(소비자 경유)가 기존과 동일
- [ ] takeover/claim/resolve의 방문자·콘솔 관찰 결과가 컷오버 전과 동일(parity)
- [ ] 기존 test_escalation·test_session_console·hitl e2e가 새 경로로 GREEN
- [ ] 백엔드 풀스택 + hitl e2e GREEN
