## What to build

신규 고객이 Operator 없이 직접 가입해 조직과 첫 관리자가 된다. `조직 이름 + username + password`만 받아
Tenant + 그 조직의 **첫 Tenant Admin**을 만든다. 이메일은 쓰지 않으며, 조직 이름이 곧 전역 unique한 로그인
식별자가 된다.

- 가입 deep module: 이름 정규화(대소문자·공백 무시)로 중복 검사 후, 통과 시 Tenant(+TENANT_KEY)와 첫
  Admin TenantAgent를 한 트랜잭션에 생성. 중복 이름이면 거부.
- 공개 엔드포인트(`auth=None`): {tenant_name, username, password} → 생성 + 가입 직후 로그인 가능(토큰/세션
  발급). 가벼운 IP 레이트리밋으로 남발 억제.
- `Tenant.name` 전역 unique 제약. 로그인은 기존 `tenant_name + username + password`를 유지하되 같은 정규화를
  거쳐 결정적으로 동작(같은 이름 조직이 둘 생겨 로그인 불능이 되는 일 없음).
- 어드민 UI: 공개 가입 페이지(조직 이름·username·password) + 가입 성공 시 로그인 상태로 진입.
- Operator의 수동 Tenant 프로비저닝 경로는 그대로 공존한다.

## Acceptance criteria

- [ ] 가입 시 Tenant + 첫 Admin TenantAgent가 생성되고, 그 자격으로 즉시 로그인된다
- [ ] 중복 조직 이름(대소문자·공백 변형 포함)은 거부된다(명확한 오류)
- [ ] `Tenant.name`에 unique 제약이 걸려 이름+username 로그인이 결정적이다
- [ ] 어드민 가입 페이지에서 끝까지 가입→로그인이 동작한다
- [ ] Operator의 기존 Tenant 생성 경로가 계속 동작한다
- [ ] 가입·중복거부·가입후로그인 백엔드 테스트 + 가입 페이지 vitest 그린
