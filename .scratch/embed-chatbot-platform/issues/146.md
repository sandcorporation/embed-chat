## What to build

`SessionEscalated` 도메인 이벤트를 소비해 Tenant webhook(Slack/Discord/Generic)을 발사하는 소비자 핸들러를 만든다. 기존 `dispatch_webhook_task`의 로직(webhook 포맷·발송)을 재사용하되, 트리거를 Celery `.delay`가 아니라 **이벤트 소비**로 바꾼다.

- group=`webhook` 핸들러 등록. 145의 멱등(processed_events)·백오프/DLQ를 그대로 활용 → best-effort였던 webhook이 **at-least-once + 재시도 + DLQ**로 승격.
- 이 슬라이스는 소비자만 — 생산자(생산 지점에서 SessionEscalated 발행)는 컷오버(151)에서 연결. 검증은 **버스에 SessionEscalated를 주입**해 수행.

## Acceptance criteria

- [ ] 버스에 주입된 SessionEscalated가 해당 Tenant webhook을 1회 발사한다(실 HTTP 수신 서버)
- [ ] 같은 이벤트 재전달 시 webhook 이중발송 없음(멱등)
- [ ] webhook 수신 실패가 백오프 재시도되고 소진 시 dead-letter로 간다
- [ ] webhook_type/url 미설정 Tenant는 no-op
- [ ] 실 Redis+Postgres+HTTP 수신 서버 기반 테스트 GREEN, 백엔드 풀스택 GREEN
