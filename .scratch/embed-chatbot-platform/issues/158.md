## What to build

per-Tenant vision 모델로 이미지를 전사하는 경로를 포트에 꽂는다.

- 전용 경계 `transcribe_image(provider, image_bytes, mime_type) -> str` — 전사 전용 프롬프트(플랫폼 상수, ADR-0009 가드레일: "보이는 텍스트만 그대로 전사, 추론·번역·요약·교정 금지, 판독 불가 시 빈 출력") + provider-agnostic 이미지 content block + temperature 0. `complete_text` 재사용 안 함(Fake 격리).
- `VisionOCR` 어댑터 — `LLMProvider` 보유, `transcribe`가 경계를 호출.
- TenantConfig OCR Provider 필드(`ocr_provider_type`·`ocr_base_url`·`ocr_api_key` 암호화·`ocr_model`) + 마이그레이션. dim 없음.
- 리졸버 `ocr_provider(config) -> LLMProvider` — `LLMProvider` 재사용, anthropic 포함 모든 타입 지원. 폴백: 설정됨→provider / dev·test 미설정→Paddle 신호 / prod 미설정→ValueError(embedding_provider 패턴).
- `get_ocr_backend(config)`가 ocr provider 설정 시 VisionOCR을, 아니면 Paddle을 반환하도록 분기.

## Acceptance criteria

- [ ] `transcribe_image`가 이미지+마임을 받아 provider+vision 모델로 메시지를 만들고 전사 텍스트를 반환(Fake 경계로 검증), 가드레일 프롬프트가 실린다
- [ ] OCR Provider 설정 시 `get_ocr_backend`가 VisionOCR을 고르고, 미설정 시 dev/test는 Paddle, prod는 에러
- [ ] `ocr_provider`가 anthropic 타입도 LLMProvider로 해석한다
- [ ] ocr_* 필드가 마이그레이션으로 추가되고 api_key는 암호화 저장
- [ ] VisionOCR(Fake 경계) + 리졸버 분기 테스트 GREEN, 백엔드 풀스택 GREEN
